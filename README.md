### Веб-сервис для семантического анализа упоминаний культурно-исторических объектов в пользовательском контенте

В рамках настоящей работы разработан веб-сервис (реализован на фреймворке FastAPI), предназначенный для автоматизированного выявления и контекстного анализа упоминаний культурно-исторических объектов в неструктурированных текстовых источниках — туристических блогах, обзорных статьях и пользовательских отзывах. Сервис позволяет выполнять поиск по заданному набору объектов в сочетании с релевантными ключевыми словами, что обеспечивает возможность фильтрации семантически значимых фрагментов.

Поисковая подсистема реализована на базе двух альтернативных метапоисковых движков с открытым исходным кодом — SearXNG и OpenSERP, что обеспечивает гибкость при интеграции с различными источниками данных и позволяет нивелировать ограничения отдельных поисковых агрегаторов.

Этап смысловой обработки полученных результатов (оценка релевантности, извлечение целевых суждений и фактографической информации) выполняется с использованием больших языковых моделей (LLM). Архитектура сервиса предусматривает два способа взаимодействия с LLM:

1. **Локальный режим** — задействуется модель, развёрнутая через платформу LM Studio (протестировано на *Meta‑Llama‑3.1‑8B‑Instruct*). Данный вариант не требует финансовых затрат, однако предъявляет высокие требования к вычислительным ресурсам: на типовых персональных компьютерах время обработки одного запроса может достигать нескольких часов. Для практического применения в исследовательских проектах предусмотрена контейнеризация с использованием Docker, что позволяет выполнять развёртывание на серверных мощностях с ускорением вычислений.

2. **Удалённый режим** — используется коммерческая модель, предоставляемая провайдером LLM (протестировано на *GPT‑OSS‑20B* в составе облачной платформы Yandex Cloud). Данный подход обеспечивает высокую скорость анализа за счёт платного доступа к вычислительным ресурсам провайдера и рекомендован при необходимости оперативной обработки больших объёмов данных.

Выбор между локальным и облачным бэкендом осуществляется пользователем на этапе конфигурации сервиса в зависимости от доступных вычислительных мощностей и допустимых временных затрат.
